# 每篇文章的三 Sheet 交付契约

## 文件与语言

默认每篇一个 `<slug>-optimization-record.xlsx`，且只包含三个 Sheet，顺序为：

1. `内容修改`
2. `代码问题`
3. `人工后续检查`

一个工作簿只记录一篇文章。所有完成文本优化的文章同时交付`<slug>-review.html`内容预览；不相关/无改动可只交Excel说明，不伪造预览。内部另留`<slug>-wp-content.html`纯正文；研发仅接收按批次打包的最新Excel，HTML均为审阅物而非上传模板，见[交付边界](wp-delivery.md)。不增加第四个总览/信息增量/权威数据Sheet、分数表或独立审核报告。批量任务同样逐篇交付；研究、来源和检查的中间文件可留作过程数据。

原因、状态、备注和技术建议用中文；原文片段逐字保留用户提供的HTML基线，修改后正文使用英语，可直接插入或替换。目标读者为北美及其他英语国家消费者；地区限定在摘要/备注中记录，不能将这些生产字段写进读者正文。Excel 中的修改是已写好的候选内容，不代表已经应用到网站。

## Sheet1：内容修改

顶部用简短键值摘要区记录文章标题、原文 URL/文件、基线版本及选择依据（线上稿含获取时间）、目标市场/正文英语、所属站点、相关性及理由、意图基线与 Query 依据（未提供就明确注明）、用户限定范围和内容完成状态。待改稿与线上稿的已发现差异单独备注，不混用原文片段。不得为了这些字段新增 Sheet。分别记录文字交付状态、授权正文质量、锁定模块人工待办和技术状态。锁定模块即使有核心问题也不阻断本轮优化交付；可记“正文通过；模块待人工后续优化”，不可宣称所有模块无问题。模式与重构依据、有效信息保留映射也在本Sheet记录。

下方主表固定列：

| 字段 | 填写要求 |
|---|---|
| 修改ID | 单篇唯一，按原文顺序排列 |
| 位置/原文锚点 | 标题路径、段落次序、可精确定位的锚点；新增需写明在何处之前/之后 |
| 操作 | 新增/删除/修改 |
| 原文内容 | 修改/删除写完整目标片段，不能只概括问题或省略；新增写“不适用（新增）”，锚点在位置列保留 |
| 原始HTML片段 | 修改/删除完整逐字片段；新增写不适用，并提供独立插入锚点HTML |
| 修改后HTML片段 | 研发可直接应用的完整代码，保留范围内原有链接及属性；删除为空。新增链接按用途设置属性 |
| 修改后内容 | 可直接使用的完整新文；删除写“删除（不替换）” |
| 问题与修改理由 | 具体问题，以及为何该改动满足意图；不能只写“提升质量” |
| 信息增量/用户价值 | 实际补足什么、如何帮助用户；纯删除/纠错如无新增信息如实注明 |
| 对应输入建议 | 建议编号或原建议的准确摘录；自主发现写“自主诊断” |
| 来源与核验 | 来源 URL＋支撑的事实＋访问日期/必要版本；无外部事实可写“不适用”并说明 |
| 状态 | 已完成修改内容/待核实/待确认；不得将未写好内容标为完成 |
| 备注 | 找货要求、后续挂链或局部限制；无则写“无” |

一个修改项对应一个可独立执行的编辑动作。较长内容按自然段/表格行拆为有序、相互不重叠的修改项，不能用省略号截断，也不能将整篇塞进一个单元格掩盖全量重写。不得让多个替换项重叠作用于同一原文而无法应用。

完整原文与修改后内容必须呈现实际文本。新增段落需有定位锚点；修改片段内的准确、有用细节仍须保留。不能把“已补充比较”“增加三个商品”当作新正文。正文可新增已核实的品牌/商品类型建议；已有商品卡锁定，不输出生产占位。

同一 Sheet 主表之后可有简短“建议处理记录”区，仅记录未形成编辑动作的建议：原文已满足、重复建议合并到哪个修改ID、未采用原因、冲突待确认。避免把未发生的修改伪装为主表行。

同一Sheet记录全文内容问题；人工后续事项和可选配图移至Sheet3，不把未修内容伪装为修改行。另在同一 Sheet 的“内容复核记录”区简要记录 LLM 对意图、细节保留、信息增量、关键事实与文案泄漏的复核依据、结论及未解决项。保留未改但已核实的关键事实列出论断/位置、来源、核验状态；范围外发现仅作记录。与文件/程序检查结果分开标注，不额外增加第四个 Sheet，不把未改内容填成修改项。

## Sheet2：代码问题

顶部注明检查输入的具体版本/URL与范围、检查时间、已检查和未检查的内容。检查范围须与实际证据相符；本地 HTML 不是线上状态，线上技术证据也不能替换 Sheet1 的待改基线。

| 字段 | 填写要求 |
|---|---|
| 问题ID | 单篇唯一编号 |
| 位置 | URL、标签、属性、模板区域或代码位置 |
| 类型 | robots/canonical/Schema/H1实现/状态码/渲染/链接实现/移动端/性能/其他代码问题 |
| 问题与证据 | 实际代码/响应/渲染现象，区分已观察与推测 |
| 可能影响 | 对抓取、索引或理解页面的具体影响，不保证排名结果 |
| 修复建议 | 可执行的技术处理建议，不表示已经修改 |
| 优先级 | P0/P1/P2/待判断，依证据和影响判断 |
| 验证条件 | 修复后如何确认、检查什么响应或页面行为 |
| 状态 | 待处理/待验证/未检查/本次检查范围内未发现问题 |

只记录有证据可能影响Google抓取、渲染、收录、规范化、页面理解或搜索展示的代码与技术实现问题，不把普通排版偏好、素材授权、商品事实、团队链接属性约定或一般上传操作当作抓取/排名故障。文章内容缺项、缺商品信息或待找货挂链进入 Sheet1，不混入 Sheet2。与旧文重复的内容策略疑点也在 Sheet1 备注，不假装成已经确定的重定向技术需求。

## 特殊结果

- **无需修改**：Sheet1 摘要写理由，主表无虚构修改行；按可获取材料正常检查 Sheet2。
- **不相关**：Sheet1 写站点、文章主题、不相关原因与“未优化”；Sheet2 范围写“未检查：站点相关性判断后提前结束”，不继续研究或扫描。
- **材料不足/待确认**：保留已完成的独立修改，具体未完成项与原因写清楚，整体标“部分完成”或“待确认”；不能把没做的研究写成完成。无原文时不编造对照文本。
- **技术未查或范围有限**：写明缺少完整页面/源码/线上响应等限制。已检查范围无发现可以记录一条范围结论，不能扩大成整页、全站或 Google 收录正常。
- **内容完成、技术待处理**：两个状态并存，不因代码问题撤销内容成果，不宣称已上线、可发布或技术已修好。

## Sheet3：人工后续检查

字段：事项ID、原文位置/组件ID、类型、问题与依据、建议动作、验收条件、影响范围、状态。锁定模块的核心问题明确标注重要性，由人工后续优化，不作为正文优化阻断项或单独分组依据；正文自身事实/逻辑错误不能转到此处逃避修复。记录锁定模块问题、图片授权疑点、可选配图与部署后人工抽查；无事项写无，不硬凑。技术项只引用Sheet2 ID；不把普通文本问题从Sheet1移走。历史“可选配图留Sheet1”的口径在本项目改为Sheet3。

## HTML交付模式

内部保留review.html阅读预览与wp-content.html纯正文，均与Excel应用全部文字修改后的候选稿一致；保留原模块及源片段属性。阅读预览可用独立易读CSS，不将预览CSS写入Excel或生产代码。研发交付文件夹与ZIP仅含最新逐篇Excel，不含HTML、旧版、~$锁文件或运行记录。

## 交付检查

1. 每篇文件独立、恰好三个正确名称且顺序正确的 Sheet，无隐藏的旧版 Sheet。
2. 原文片段在唯一基线中能精确定位；新增锚点存在，删除有理由，替换完整且不重叠。精确匹配可由程序辅助；由 LLM 将修改放回全文复核意图、已有有效细节和建议处理，不以匹配成功代替语义复核。
3. 由 LLM 对照实际来源复核新增、纠正及保留的关键事实，商品类型与真实型号表述清楚；信息增量不是单纯篇幅增加。未经核实不得继承为已验证事实，也不得把缺少 SKU 当未完成内容。
4. 面向读者的新文不含内部流程、未来商品模块、占位、自我削弱套话或虚构实测；中文备注与新文分栏。
5. 技术证据、范围与状态真实，内容事项不混入代码问题。
6. 生成 Excel 时按可用的 spreadsheets 技能渲染/预览并重新读取检查：换行、列宽、行高、冻结表头、筛选及文本完整性。长段落可拆成相邻自然段修改项；单元格超长时不得静默截断。避免原文以 `=` 等字符开头被当成公式，保留为文本；不得有公式错误、乱码或不可读的裁切。
7. 交付HTML时检查Excel改文与内容预览一致。不将 Excel 生成成功等同于线上修改或发布审核通过。

文件/程序检查与 LLM 内容复核均完成且结果已记录，才可说明两者通过；脚本通过不能代替任何语义或事实性的完成判定。无内容修改、不相关等提前结束场景仍由 LLM 给出相应依据，不伪造未执行阶段的复核。

可选配图未执行不影响正文完成或质量结论，记录于Sheet3，不再增Sheet、不输出复杂找图任务。已有图片错配仍作为一致性问题处理。正文修改交付与内部核验记录分开，HTML与Excel必须同步更新，包括商品过渡和链接代码。

## 保留与增量的独立记录

仍在Sheet1记录：有效信息单元→原位置→新位置或纠正/删除理由；研究规划的读者问题、原覆盖、待验证结论、所需证据及位置；完成后新增判断价值、来源、落点与未解决状态。分别验收保留、补缺和新增答案支持度，三项不互相抵消。字数只描述篇幅，不证明质量；配图可选项不参与硬性验收。

缺陷清单与增量机会分开记录，但仍放在Sheet1；增量机会在改写前建立，完成后写具体新增判断、可改变的选择、来源与正文落点。结构改善单独标记，不计为研究增量。访问受阻、混款或重复转载不得记录为已核验的独立证据。

最新验收：原始/修改后文本与HTML语义一致；程序回放每条修改验证精确匹配及模块保护，不把整篇替换作为可执行修改。文字修改范围含既有链接时链接原字符串保持不变；修正需求转待办。新增链接需完整代码。
