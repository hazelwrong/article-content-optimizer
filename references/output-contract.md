# 输出契约

## 1. 单篇文章正式交付

每篇文章最终只交付两个文件：

1. `<slug>-optimized.html`
2. `<slug>-optimization-record.xlsx`

审核 JSON、证据包、静态检查日志、阶段快照和主控台账属于过程数据，不算单篇文章的正式交付文件。

### 1.1 最终优化 HTML

- 可直接复制到 WordPress 后台或进入既定发布流程。
- 不保留模板变量、占位符、TODO、待确认标记、伪造引用或无法核验的数据。
- 正文中的事实、数字和权威论断必须能回溯到 Excel 的“信息增量”或“权威数据”Sheet。
- 不擅自改动站点模板、robots、canonical、schema、全站 CSS/JS 等非内容层配置；发现后记录到“非内容问题”Sheet。

### 1.2 Excel 优化记录

工作簿必须包含且仅包含以下 5 个 Sheet，名称不得改写：

1. `总览`
2. `内容优化项`
3. `信息增量`
4. `权威数据`
5. `非内容问题`

工作簿必须填入本次文章的真实记录，不交付空模板。面向人工的说明、待办和备注统一使用中文。

一个工作簿只对应一篇文章，不得把多篇文章的记录合并到同一个 Excel。

## 2. Sheet 字段

### 2.1 总览

`总览` 只有一行数据，并且只包含以下 4 列：

| 初始诊断分 | 优化后分 | 信息增量前 | 信息增量后 |
|---|---|---|---|
| S20 的数值诊断分 | S70 的同口径数值评分 | 无增量/弱增量/中等增量/高增量 | 无增量/弱增量/中等增量/高增量 |

不要在 `总览` 增加文章 ID、标题、Slug、文件路径、发布日期、硬闸门、发布决策、备注等字段；这些属于文件命名、过程台账或其他明细，不属于本 Sheet。

“初始诊断分”和“优化后分”必须采用同一版 `article-review-sop` 的评分维度和分值口径。`初始诊断分`用于展示内容优化前的质量基线，即使命中硬闸门也不能抵消“不发重改”的决定；无法可靠评分时填写“信息不足”，不得编造数值。

### 2.2 内容优化项

这里只记录文章内容本身实际改了什么，不记录流程动作、硬闸门、分控路由或文件搬运。

| 字段 | 说明 |
|---|---|
| 优化项ID | 单篇内唯一编号 |
| 内容优化类型 | 如“补充细节”“增加数据”“重构大纲”“纠正逻辑”“改写表达”“消除重复”“增强决策支持” |
| 内容位置/模块 | H2/H3、段落或模块名称 |
| 优化前内容状态 | 原文存在的具体内容问题 |
| 优化后具体内容 | 实际增加、删除、重组或纠正的内容 |
| 新增细节/数据 | 本项新增的事实、细节、方法、边界或数据；没有则填“无” |
| 是否有信息增量 | 是/否 |
| 是否仅表达调整 | 是/否 |
| 对用户的作用 | 该改动如何帮助用户理解或决策 |
| 复核状态 | 通过/需人工复核/未通过 |
| 完成日期 | YYYY-MM-DD |
| 备注 | 中文备注 |

本 Sheet 的全部行都只属于当前 Excel 对应的这一篇文章。以下内容不算合格的“内容优化项”：运行了审核、命中某硬闸门、进入某阶段、生成了文件、等待人工处理。应写成文章中发生的真实变化，例如“在尺寸测量部分增加水箱最高点、进水阀和墙面踢脚线三处净空测量，并补充 2–5 厘米安装余量”。

### 2.3 信息增量

| 字段 | 说明 |
|---|---|
| 增量ID | 单篇内唯一编号 |
| 信息增量 | 相比原文新增加的事实、方法、场景、边界、比较或决策信息 |
| 类型 | 事实/方法/场景/边界/比较/决策支持/其他 |
| 用户价值 | 为什么能帮助读者完成任务或降低决策成本 |
| 写入位置 | 最终 HTML 中的章节或模块 |
| 信息增量URL | 用作记录和人工审核的来源 URL；不适用则填“不适用”并说明 |
| 来源等级 | A/B/C 或项目约定等级 |
| 是否进入正文 | 是/否 |
| 人工审核点 | 中文说明人工需要确认什么；无则填“无” |
| 采集日期 | YYYY-MM-DD |
| 状态 | 已核验/待人工核验/未采用 |

本 Sheet 的全部行都只属于当前 Excel 对应的这一篇文章。

### 2.4 权威数据

| 字段 | 说明 |
|---|---|
| 来源ID | 单篇内唯一编号 |
| 权威数据/论断 | 最终正文采用的具体数值、标准、定义或权威结论 |
| 数值/单位/适用条件 | 数据值、单位、适用范围和必要限定 |
| 来源名称 | 机构、标准、论文或官方页面名称 |
| 来源URL | 可供文章引用和内链评估的 URL |
| 来源类型 | 官方机构/标准组织/学术论文/制造商文档/其他 |
| 正文位置 | 最终 HTML 中的章节或模块 |
| 文章页使用方式 | 正文引用/参考来源/内链候选/背景核验 |
| 采集日期/版本 | 页面采集日期或标准版本 |
| 是否进入正文 | 是/否 |
| 核验状态 | 已核验/待人工核验/不采用 |
| 备注 | 中文限定、冲突或版本说明 |

没有增加权威数据时仍保留该 Sheet，并写一行“本次未增加权威数据”，同时在备注中说明原因；不得为了填表而编造数据或来源。

本 Sheet 的全部行都只属于当前 Excel 对应的这一篇文章。

### 2.5 非内容问题

| 字段 | 说明 |
|---|---|
| 问题ID | 单篇内唯一编号 |
| 问题类别 | H1/robots/canonical/schema/索引/模板/页面性能/商品模块/其他 |
| 具体问题 | 审核发现的非文章内容质量问题 |
| 证据 | 检查结果、页面位置或截图/日志说明 |
| 负责人 | SEO/开发/编辑/人工审核/其他 |
| 时限 | P0/P1/P2 或明确日期 |
| 是否阻止发布 | 是/否 |
| 建议查找位置 | 中文说明应在哪个后台、模板或代码位置检查 |
| 处理动作 | 中文说明建议的修复动作 |
| 关闭条件 | 可验证的完成标准 |
| 人工备注 | 中文补充项；无则填“无” |
| 状态 | 待处理/处理中/已关闭/不适用 |

没有发现非内容问题时仍保留该 Sheet，并写一行“本次未发现非内容问题”。

本 Sheet 的全部行都只属于当前 Excel 对应的这一篇文章。

## 3. 过程结构化数据

优化过程可维护以下中间对象，供主控恢复、路由和生成 Excel 使用：

```yaml
article_id: string
route: MERGE | LIGHT_REFRESH | DEEP_REWRITE | HOLD | OUT_OF_SCOPE
baseline_review:
  diagnostic_score: number | 信息不足
  information_gain_level: NONE | LOW | MEDIUM | HIGH | 信息不足
  decision: 通过上线 | 先发后改 | 人工复核 | 不发重改
optimized_review:
  total_score: number | 不评分（命中 HG-X） | 信息不足
  information_gain_level: NONE | LOW | MEDIUM | HIGH | 信息不足
  decision: 通过上线 | 先发后改 | 人工复核 | 不发重改
content_change_rows: []
information_gain_rows: []
authority_data_rows: []
non_content_issue_rows: []
deliverables:
  optimized_html: string
  optimization_record_xlsx: string
```

这部分可以保存为 JSON、JSONL 或数据库记录，但默认不作为单篇文章的正式交付。

## 4. 批量任务

批量任务可以另外维护主控台账，用于记录 `article_id`、阶段、状态、重试次数、错误、负责人和产物路径。主控台账属于内部编排数据，不改变“每篇文章分别交付一个 HTML 和一个独立 Excel”的规则。

每篇文章必须独立生成自己的 HTML 和 Excel，不把多篇文章混入同一个单篇交付工作簿。

## 5. 交付校验

- 每篇文章正好有一个最终 HTML 和一个 Excel。
- 每个 Excel 只包含一篇文章的数据，不得跨文章合并。
- Excel 的 5 个 Sheet 名称和顺序正确，无额外 Sheet。
- “总览”只有一行数据和 `初始诊断分`、`优化后分`、`信息增量前`、`信息增量后` 4 列。
- “内容优化项”只写实际内容改动，且能区分信息增加与仅表达调整。
- 信息增量 URL 和权威数据来源 URL 可追溯，待人工确认项用中文写清。
- 最终 HTML 不含模板变量、占位符、TODO 或未完成标记。
- Excel 无公式错误、乱码、截断或明显排版问题。
