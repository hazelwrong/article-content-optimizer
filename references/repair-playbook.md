# 局部修复与最终技术检查

## 先把问题落到位置

通读全部原文与建议，按稳定的标题路径、段落序号、完整原文锚点定位。相同句子出现多次时附所属章节和次序，不能只给一句模糊摘录。允许跨相邻段落修复同一个问题，但不要把全篇打成一个“替换正文”项。

| 问题 | 实际处理 | 保留边界 |
|---|---|---|
| 某事实错误或陈旧 | 检索并核实，改对应论断与必要关联句 | 不顺便改其他正确解释 |
| 步骤、条件或例子缺失 | 在相应位置补完整可执行内容 | 保留原有步骤与有效细节 |
| 重复、偏题或生产说明 | 删除具体片段并写明理由 | 重复段中的独有信息必须保留 |
| 比较缺少一侧或维度 | 研究两侧，同口径补缺项并解释差异 | 不将比较文改为单品推荐 |
| 推荐泛化、商品模块缺失 | 研究适合的商品类型/品牌商品，补理由、人群和关键字段 | 不要求现有 SKU 或链接齐全，不只留空槽 |
| 标题与内容承诺不符 | 从 Query 和话题识别任务，优先补齐承诺对应内容 | 不因只有一个商品或缺资料而改型；措辞修正不能迁移意图 |
| 多处内容质量差 | 先判框架是否成立；局部修复或有依据地结构重构 | 按已授权同意图重构规则保留有效信息、记录迁移，不以条数决定重构 |
| 与旧文疑似同意图 | 提供具体重叠证据，记录内容策略待确认项 | 不自动合并、删页、301 或将本页改成另一任务 |

用户建议是重要输入，不能逐条孤立执行。建议已满足、重复或有冲突时记录处理结论；明显会删除必要细节或改变意图的建议说明冲突，先完成其余独立修改。技术建议转 Sheet2，不抢占正文优化。

## 新增信息的要求

先指出读者原来无法完成什么任务，再研究并补上帮助完成任务的信息。常见增量包括可执行步骤、同口径比较、容易漏掉的尺寸/兼容性条件、按场景选择的依据、有来源的商品事实，以及从已有数据得到的透明计算。

研究同行用于发现内容覆盖与缺口；对网络资料进行核实和组织，不能把来源搬运、同义改写、更多商品名或更多字数当作增量。只需要删除一段时允许没有新增内容，不机械要求每项都产生新知识。

局部研究仍不足以支撑具体论断时，改写为有依据的内容或将该项标记待核实。不得用“无法验证”推断事实为假，也不得因此停止其他优化、改文章意图或删掉整块有用内容。

## 商品内容

- 按意图补齐合适的商品模块，可增加候选、筛选字段和对比维度；数量由读者任务决定，不设固定 3 个或 5 个门槛。
- **商品类型**：写出适合的结构、功能、材料或筛选要求，说明适用场景与取舍。将建议写成选品条件，不能假称某个未找到的商品已具备全部条件。
- **品牌/型号**：访问品牌官方商品、系列、规格或支持页，确认实体、版本、地区与具体事实；允许推荐并供后续 affiliate 挂链。不要把品牌导购改成无品牌替代文，也不要要求先存在 DHgate 商品链接。
- **真实比较**：适用于具体型号的数据需逐项核验；官网营销结论不能未经解释就当成独立测试结果。
- 推荐内容应能直接供读者使用；找货要求、待挂链接等仅写在 Sheet1 的中文备注，不写进读者正文，也不列为代码问题。

## 信任和内容泄漏

删除 Prompt、调试语句、编辑指令、未来模块说明、待补商品通知等生产残留。不得新增“本文没有做任何测试/实验”一类无助于判断的自我削弱段落；同样不得暗示实际未发生的测试或体验。

安全、适用范围、动态规格等对读者有用的限制应放在相关结论附近。已有真实商业披露不应误删；未来可能挂链接、尚无特定合作关系的生产计划不是可发表的商业披露。详细规则见 [evidence-policy.md](evidence-policy.md)。

## 内容完成后的技术检查

先复核内容，再按实际可访问材料检查，并汇总过程中的技术发现。检查范围包括可能影响 Google 抓取、索引或理解页面的 HTTP 状态、robots/meta/X-Robots-Tag、canonical、HTML 标题结构、Schema 与可见内容一致性、内容渲染、链接可抓取性、移动端及性能实现。性能问题需有测量或具体实现证据，不能从“有 JS”推断慢或排名下降。

- **证据区分**：完整线上页面、完整本地 HTML、正文 HTML 片段、纯文本，能证明的范围不同。
- **候选不是结论**：本地 HTML 的 noindex 可以确认该文件含指令，不能证明当前线上仍 noindex；脚本报缺 canonical 也需判断输入是否包含 head。
- **边界**：H1 文字不清属于内容；H1 标签重复/缺失属于实现。商品推荐内容缺失属于内容；商品模块有实际渲染/链接错误才是代码问题。Schema 更新建议属于技术，即使由正文变更引起也需带出。
- **状态**：已发现问题写“待处理”；推测写“待验证”；拿不到源码/线上响应写“未检查”。已检查范围无发现可写“本次检查范围内未发现问题”，同时明确未查范围。
- **交付**：逐条写代码位置、现象和证据、可能影响、修复建议、优先级与复查方法。P0 为有证据的严重抓取/索引阻断；其余按实际影响判断，不把所有问题列为阻断。
- **不执行外部变更**：不改模板、robots、canonical、服务器配置、发布状态或重定向。技术未修复不撤销已完成的内容工作，也不代表页面可发布。

静态脚本只能提供局部线索；意图判断、事实验证、保留细节、Schema 语义一致性和线上可访问性仍需实际检查。
