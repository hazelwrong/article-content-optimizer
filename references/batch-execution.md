# 批量隔离、并行与续跑

## 台账与派发

先按站点、完整URL、唯一输入HTML路径与SHA256建立清单，匹配该URL的Query与全部建议并记录来源sheet/行。无Query按文章主题判断；同URL多稿冲突只暂停该篇，不猜最新。已完成且基线相同不重复优化；输入hash变化则明确新版本，不能复用旧操作。

用户授权subagent时，初期每批20篇、最多3篇并行（工具容量不足则降低）。每个worker一次负责一篇完整流程，独立目录，不写其他文章或全局台账。主agent单独维护派发/完成状态与批次打包，防止重复领取。实际容量或用户指令优先，不将并行数量当质量指标。

worker必须实际读取本篇HTML、Query与全部建议及当前skill；执行LLM诊断、独立信息增量研究、改写、合并复审和程序校验。不能只靠脚本批量替换、套上一篇结论或因赶进度省略站外研究。共享来源可用，但逐篇确认型号、版本与论断支撑。

## 完成与验收

每篇返回：输入hash、意图/站点判断、具体新增答案及证据、有效信息保留、正文复审结论、Excel回放/模块保护结果、人工待办和技术范围。主agent核对所有交付的完整性、一致性与事实支持记录，复读正文结论和高风险改动；发现错误退回该篇，不能仅凭worker自评接收。

区分queued/in_progress/completed_text/needs_text_revision/input_conflict/unrelated；模块待办独立字段，不改成文本阻断状态。只有文件及内容检查完成才记completed_text；中断保留原任务与未完成阶段，下次核对文件/hash后续跑。不得仅凭文件存在或字数增长判完成。

首批20篇完成后停下交用户验收，再按反馈推进后续；不是一次自动开跑全部余量。每批研发目录只放正式Excel，预览独立目录；台账/研究/过程数据不进交付目录。每篇三Sheet，不增第四Sheet；锁定模块问题归人工后续，不单独分阻断包。详细输出与验收沿用output-contract和wp-delivery。
